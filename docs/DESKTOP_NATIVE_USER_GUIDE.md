# DMN Desktop 原生用户手册

## 安装与升级

支持 Windows、DSH Desktop/SDK 0.2.1-rc.3、Node 24.14+（24.x）、npm，首次安装需要 npm registry 网络。解压完整发布 ZIP 或克隆仓库，正常退出 Desktop，然后在根目录运行：

```powershell
powershell -NoProfile -File scripts/install-native.ps1 -Mode check
powershell -NoProfile -File scripts/install-native.ps1
```

安装器先本地备份 Desktop Profile 的清单/补丁，按锁文件安装依赖，检查支持版本并通过官方 CLI 注册本地链接。已有实例在升级前生成停机成套备份；异常时停止并保留日志，不修改 DSH 核心，也不授予旧插件版本豁免。请保留解压目录，DSH 将从该目录加载插件。修改宿主模块后必须完整退出并重新启动 Desktop，热更新不足以证明 Host 依赖已更新。

若失败，原 Profile 备份位于 DSH Home/dmn/install-backups/<UUID>。优先修复错误并重跑；不要覆盖整个已变化的 Profile。回退到保留的旧发布目录重新运行安装器，必要时用相同 SDK/Schema 的成套备份恢复。未知新 Schema 会被拒绝，不能直接降级数据库。

## 首次配置

打开左侧“群聊” 的“连接设置”（顶部齿轮也可进入），或官方设置的“群聊”页。配置数据库绝对路径、日志目录、提供商凭据引用与两节点模型。默认数据在 DSH Home/dmn/instances/default/queue.sqlite，日志在 dmn/logs，普通配置在 dmn/settings.json；代码更新与卸载不会删除这些文件。已有实例须选择原数据库和对应模型，节点会话及记忆命名空间不可重绑。日志只记录生命周期事件/PID，不记录消息、私有 Prompt 或密钥。

默认凭据引用 DMN_DEEPSEEK_API_KEY。可以在密码输入框保存新值到官方 DSH 安全凭据服务，普通文件只保存引用；留空表示保留。默认引用缺失时才使用启动环境 DEEPSEEK_API_KEY，其他自定义引用不回退。保存后只读重连，不执行模型。只读检查只报告凭据是否存在，并非计费模型探测；真实调用仅由明确话题/输入授权触发。

## 交流与预算

A/B 卡片显示独立模型与真实运行状态；点击卡片即可选择收件人，悬停查看固定根会话。DMN 内部不再使用侧栏，顶部切换话题，中间按群聊显示消息，底部输入框保持可见。加号新建话题，活动图标进入运行管理。DSH 官方导航保留。

点击“新建话题”，选择定向交流或双节点讨论并检查授权预算。创建定向话题不会启动模型；选择收件人发送输入后，只唤醒该节点。输入框中 Ctrl+Enter 发送，Enter 换行。授权讨论会从选定节点开始，在最多 12 次调用、5 分钟和可见 Token/估算费用约束内运行。状态条提供暂停、继续（恢复原预算）、结束与详情。估算费用沿用项目计价单位，并非实时账单；诊断中的实际费用未知时显示 null。恢复不会扩大预算。

时间线用真实 sender → recipient、replyTo 与完成轮次关联输入和回复。自己的消息靠右，A/B 采用不同头像与配色，回复编号和完成轮次在“回复与轮次”中展开。静默、拒绝、失败、未知与正式回复分别显示。消息正文是纯文本。较早消息可分页，刷新状态回到最新快照。弹窗支持 Escape 关闭和 Tab 焦点循环。

响应丢失会保留完整原请求/幂等键；重开面板只读，不自动重发。先检查话题和时间线，再用原请求重试。相同键和参数返回同一入库结果；更改参数会被拒绝。服务拒绝的请求不会无限占用待确认标记。关闭面板不停止当前服务，正常退出宿主会停止新调度并等待当前有限活动结束。

## 节点系统提示词

点击节点旁的齿轮，分别编辑 A/B 的系统提示词，最多 8000 字符；留空保存后使用内置 Persona。提示词属于当前数据库实例，不是全局设置；仅注入对应节点后续领取的轮次，不注入对端。固定根会话、已有历史与私有记忆保留，修改提示词不等于清除历史，也不保证模型逐字遵循。

保存不调用模型。运行中、隔离或未知轮次的节点不能修改；版本冲突须重新读取后编辑。响应丢失时“重试保存”沿用原请求，不能直接改参数重试。不要填写密钥。宿主输出协议、私有记忆隔离、工具限制与硬预算始终生效，模型不能通过聊天自行修改提示词。

v0.2.0 数据库升级到 v8：安装器在停机时先备份数据库与 Runtime，再由服务事务新增两张提示词表，不改写旧消息和会话。回退到 v0.1.x 需恢复匹配的 v7 成套备份，不直接降低 Schema 版本。

## 维护与恢复

顶部活动图标“运行管理”打开诊断与受控维护，只展示公开队列、错误类别、死信、完成证明、预算和 Token；没有跨节点记忆浏览器。证明完整时可显式对账；人工放弃必须再次输入具体 turnId 并填写原因，写入 desktop-user 审计，不退还预算。忙碌/未知 Runtime 锁不能绕过。

服务崩溃后先读取诊断。若旧 PID 已退出、所有客户端已退出、Runtime 没有锁，可输入精确实例 ID/PID/原因归档旧登记；进程存在、状态不明、Runtime 锁或审计失败都会阻止操作。不会自动移除 SDK 锁，也不会自动重放旧任务。

备份和原位恢复由一次性维护进程执行，先停止拥有的服务。备份返回 UUID，位于数据库旁的 .backups 目录，包含数据库与两节点 Runtime。恢复必须确认原实例 ID，先保留旧数据对到 .restore-previous-<UUID>，再恢复相同绝对位置。出现 .restore-incomplete 时停止操作，保留现场、旧数据和备份；不得手工删标记后直接启动。读取/重连不会自动恢复讨论。

## 卸载与发布包

正常退出 Desktop 后运行：

```powershell
powershell -NoProfile -File scripts/install-native.ps1 -Mode uninstall
```

仅移除官方插件注册，默认保留全部业务数据、配置、凭据引用及备份。删除历史属于单独操作，此安装器不提供删除开关。

维护者在干净已提交的工作区运行 npm run desktop:native:package，生成源码 ZIP、release-manifest.json 和 SHA-256 校验文件。开发测试、模拟浏览器、真实 Desktop、真实 SDK 和故障用例的结果分开记录；验收报告不代表任意故障自愈或无限长稳。
