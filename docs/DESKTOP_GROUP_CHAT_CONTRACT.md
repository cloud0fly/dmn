# Desktop 群聊与节点提示词契约（G1）

本阶段在 N5 后按用户授权改进现有双节点，不启动 P6。保留 DSH 官方导航，移除 DMN 内部侧栏；顶部选择话题，消息按群聊展示真实发送者、接收者和执行结果。停止原因、逐节点额度、待投递消息必须可见，不自动追加预算或强制模型发言。

## 提示词

仅可信本地操作员可通过 nodePrompt({nodeId}) 读取单节点自定义提示词，通过 setNodePrompt({nodeId,revision,systemPrompt,idempotencyKey}) 更新。revision 为非负整数；systemPrompt 为 null（使用内置 Persona）或 1–8000 字符。拒绝未知字段与伪造身份；Node/Memory/Gateway 工具无编辑入口。普通 nodes、队列、诊断不返回提示词。

Schema v8 增加 node_prompts 与 node_prompt_requests。更新使用事务和乐观版本校验；同节点同幂等键同参数重试返回原结果，异参数拒绝；审计只记录节点、版本、操作员和请求键，不记录正文。运行中或未知轮次节点禁止编辑，失败回滚，保存本身不调用模型。

Runner 在领取轮次的同一事务中读取对应节点提示词及版本并写入不可变执行快照；已领取/未知执行的对账使用原快照。每次 SDK 使用该节点自定义 Persona，未配置则读原文件；宿主固定安全和输出协议始终追加，不能关闭校验、工具隔离或预算。其他节点的提示词不注入本轮；已有根历史仍保留，不承诺编辑能消除历史影响。

## 迁移与回退

升级前正常停止 Desktop/服务并生成数据库及 Runtime 成套备份，v7→v8 事务建表，不改写旧消息、根 ID 或记忆。旧提示词默认 null/revision 0。旧代码不支持 v8；回退须用匹配的 v7 成套备份，不直接降低 user_version。备份支持 v1–v8，并检查 v8 两张新表。

## 验收

先离线覆盖版本冲突、响应丢失重试、重开持久化、审计失败回滚、忙碌/未知拒绝、提示注入后仍强制边界、A/B 互不注入、预算停止及旧快照对账；再测试原生桥接与浏览器保存/重开、无侧栏、窄屏、停止原因。真实模型验收固定独立测试库与最多 6 次调用，不能把模拟或 Accepted 当真实完成。
