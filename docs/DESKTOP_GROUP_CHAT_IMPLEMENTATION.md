# Desktop 群聊与节点提示词（2026-10-28，v0.2.0）

## 交付

移除 DMN 内部话题侧栏，保留 DSH 官方导航。顶部切换话题与成员，群聊按真实发送者和接收者显示头像、消息气泡、时间及回复关系，底部固定输入框。新消息在阅读底部时跟随滚动，翻阅历史时不强制跳转。采用官方字体与背景/文字/边框主题变量，未修改 DSH 核心或注册额外权限。

每节点齿轮可独立配置系统提示词，留空恢复内置 Persona。可信操作员请求经实例绑定、严格字段校验、CAS 版本控制、持久幂等与审计；忙碌/未知节点拒绝修改。Runner 领取时固化本节点提示词与版本，SDK 续接原根会话；固定边界始终追加，输出动作仍由宿主授权。公开节点列表、诊断与队列不返回提示词；节点不能通过消息编辑提示词。

预算暂停显示原因、每节点用量和仍排队的节点消息；最新静默/拒绝会给出明确反馈，不自动增加额度或强制模型往返。Topic 状态新增 pendingMessages 与 sanitized latestActivity（节点、状态、动作、抑制标记），不包含输入快照或模型原文。

## 迁移和恢复

Schema v8 新增 `node_prompts` 与 `node_prompt_requests`，迁移脚本 `sql/008_node_prompts.sql`。旧消息、Session ID、Persona 文件引用与私有记忆不变。安装器保留原有停机成套备份流程；备份校验兼容 v1–v8，v8 要求两张新增表。回退使用对应旧代码和 v7 备份，禁止直接调低 user_version。

本机正式升级前正常退出 Desktop，安装器保留 Profile 与 v7 数据库/Runtime 成套备份。重连时发现旧服务进程已退出的遗留登记，经现有维护流程确认 PID 不存在、无运行/未知轮次、无 Runtime 锁后归档登记并留审计；没有重放旧消息或清除 SDK 锁。随后 v8 服务就绪，既有 2 次完成活动保持不变。

## 自动化与实际验证

- 135 项核心离线测试通过：含新增提示词版本冲突、幂等重复/异参冲突、审计失败回滚、运行/未知拒绝、A/B 隔离、五轮硬停止、v7 升级/重开及成套恢复。
- 10 项插件/进程测试通过：含提示词读写的可信来源、精确实例绑定、维护权限与凭据隔离。
- 原生 Chromium 组件测试通过：实际组件与 Host 桥接，模拟模型；新增保存丢响应后的原键重试、重开保持、对端空提示词、无内部侧栏、窄屏及键盘操作。3 项兼容 Web 浏览器测试继续通过。
- TypeScript 与构建通过。1100px/390px 模拟浏览器人工检查；实际 Windows DSH Desktop rc3 打开群聊、保留原聊天，读取节点提示词编辑弹窗。没有替换用户现有 Persona 或向用户话题追加测试消息。
- 真实 API 使用独立测试库，共 6 次调用。前 5 次完成 A→B→A→B→A 交流，形成 4 条实际节点消息，在 TOTAL_TURNS 停止；所有完成轮次由 SDK 持久日志独立检查终态、根 ID、路由及工具边界，不能以入队回执代替完成。
- 第 6 次在同一测试实例修改 A 的提示词为 revision 2，再向其发送单次直接输入；原根会话 resume，正式回复含新 Persona 指定标记，终态独立核验通过。无额外重试或隐藏计费调用。总预留 196608 输入 / 4608 输出 tokens、估算费用 1.5 项目单位；这不是实际账单。

## 保留的失败和限制

初测的五轮消息已经完成，但断言过度要求前缀必须带「」；实际模型使用“架构：/审阅：”，初测记录为 FAIL。改为校验角色语义并对同一批持久执行只读复核，结果 PASS，没有为此再次调用模型。提示词不是逐字遵循保证。

新增浏览器测试还发现：保存按钮禁用期间焦点可能落到弹窗外，Escape 无响应；已增加窗口 Escape 处理与焦点恢复并复验。迁移测试初次使用空位置恢复时遭残留 WAL/SHM 拒绝，调整为正式保留旧数据对的原位恢复流程后通过。

现有根历史保留，编辑不会清除既有历史的影响。系统提示词是可信本地操作员配置，不是远程多用户权限体系。真实模型自行静默仍允许且会提示；不承诺任意主题必然连续发言。窄屏只在 Chromium 验证，实际 Desktop 采用常规窗口。兼容 Web 仍保留原界面，本轮配置入口仅在原生 Desktop/可信 native CLI。未推进 P6、多 Provider 或第三节点。最终构建已更新客户端；最后补充的服务状态字段需下次正常退出并重开 DSH 加载。收尾时窗口被用户最小化且自动化报告用户输入，未强行重启或中断用户操作。
